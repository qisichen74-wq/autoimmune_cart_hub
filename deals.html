交易情报

公开披露的交易与并购 · 发现层（候选）与裁定层（交易）分开呈现

这一页上没有任何金额。 库里也没有 —— 候选表一个金额列都没有。 8-K 的交易段落里常同时出现首付、里程碑上限与股权投资额，判断哪个数对应哪一项要读上下文； 抽错一个首付金额，读者没有任何办法发现它错了。所以金额只出现在 「已裁定的交易」那张表里，而那张表的每一行都必须带原文引用与逐字节可回放的定位符。
  • 4020候选文档
    单位是文档 · 不是交易 · 为什么

    这个数数的是候选文档份数：一份申报可能提到多笔交易，一笔交易也可能被多份申报各提一次。所以它既不是交易数，也不是「有多少家公司在做交易」——它唯一能回答的问题是「有多少份文档进了待读队列」。

  • 0已裁定的交易
    读过原文才落一行 · 为什么

    只有已经有人读过原文、并且原文引用能逐字节回放的交易才进这个数（回放不通过的行插不进库，有 CHECK 挡着）。所以它是一个下界，而且它不随候选池一起长 —— 候选池涨一千份，这个数照旧不动。

  • 0还没做过归属
    还没查 ≠ 查过没有 · 为什么

    「从未做过归属」是这份文档还没有被查过病名；「查过、一个已登记病名都没出现」是查过、结果确实是没有。两个数在页面上长得一样、含义相反，所以本站既不把它们相加，也不合并成一个「无归属 N 份」。

  • 3采集渠道
    渠道数 ≠ 覆盖面 · 为什么

    这个数数的是本站声明过的渠道条数。声明过不等于有数据 —— 里面既有正在跑的，也有机制建成、但还没有任何抓取对象的，还有一次都没跑过、甚至还没建成的。哪一条是哪一种，只看每条渠道标题旁边那个状态标签：本站不把「渠道已声明」渲染成「这个渠道有数据」。

疾病归属　文档中出现该病名

这不是「该病相关交易」。一份 8-K 的管线段落里列十个适应症，十个病名都会命中。

从未做过归属 0 份（还没查）查过、一个已登记病名都没出现 2657 份（查了，没有）

疾病归属那一遍有 272 条查询、约 45 分钟。它每晚随定时任务跑，但只覆盖最近 7 天的申报（窗口末端还留 2 天不标：EDGAR 全文索引有滞后，那几天的申报还查不到，标上去等于宣称查清了）。申报日更早的候选要靠一次全历史归属才能补 —— 所以「从未做过归属」这个数可能长期不是 0。一条候选可能在「已发现、未归属」的状态下停留很久 —— 这是一个声明过的滞后，不是空洞。

召回缺口：疾病归属只用 "chimeric antigen receptor" 与 "CAR-T" 去交叉， 没有用 "chimeric autoantibody receptor"（CAAR）。 因此只用 CAAR 的写法、完全不提 CAR-T 或 chimeric antigen receptor 的文档， 会出现在候选清单里但拿不到疾病归属 —— 表现是候选清单上有它、疾病页上没有它。 这不是"没有关联"，是"没查过这个组合"。 （"CAR T-cell" 不构成缺口：实测其命中集合是 "CAR-T" 的子集。）

渠道覆盖面：这个板块看得见什么、看不见什么

本板块目前只有 SEC 一条腿有数据 —— 它呈现出来像「本领域的交易清单」，实际是「在美国证监会申报的公司披露的交易清单」。 这是系统性偏倚，方向逐条写在每个渠道下面的「这个渠道看不见什么」里。

SEC EDGAR 全文检索　已建成·有数据

在美国证监会申报的发行人（含在美上市的境外发行人）提交的文件全文。 交易类事项主要出现在 8-K（item 1.01 重大协议 / 2.01 收购完成 / 7.01 Reg FD / 8.01 其他重大事件）与 425（合并相关通讯）里。

这个渠道看不见什么：

  • 非 SEC 申报人的交易本渠道系统性看不见。 在中国境内注册、未在美上市的 CAR-T 企业，其交易通常只在公司公告、港交所 / 上交所公告或中文媒体披露。 这类企业在本站 in_scope 试验的申办方里占相当比重，因此这是本板块最大的偏倚方向。
  • ⚠️ 上面这条盲区没有被量化。要给出"有多少家申办方不是 SEC 申报人"这个数字， 需要把申办方原文与 SEC 申报人名录做名称匹配，而实测已证明公司名称匹配的 真配对命中率只有约 1/22（见申办方页）—— 用它算出来的数会比没有数更误导人。 所以这里只声明方向，不给数字。
  • 双方均未上市、且都不是 SEC 申报人的交易（除非其中一方因其他原因需要申报）。
  • 未达到"重大"门槛因而无须提交 8-K 的交易。
  • SEC 全文检索索引的起始年份早于本站关注的时间窗，但并非覆盖 EDGAR 全部历史。
  • 本渠道只发现"文档里同时出现了这些短语"，不判断这份文档是否在讲一笔交易。 那一步是人工裁定，未裁定的候选在页面上一律标为"未裁定"，绝不计入交易数。

登记表 0 家公司。本渠道的机制已经建成并且每晚都在跑，但它现在没有任何抓取对象 —— 所以这里的 0 是「一家都还没登记」，不是「这些公司今天没发交易公告」。下一步不是写代码，是往 config/company_pr.yaml 里登记一家公司。
登记一家要核对四项 · 为什么

订阅源地址、robots.txt、实测 transport、核对人与日期 —— 四项缺一项代码就拒抓。凭印象填的地址返回 404 时，表现与「这家公司没发公告」完全一样，所以这里宁可拒抓。先登哪几家可以按本站试验数排序，命令写在「口径与盲区」那一页的「已声明、还没建成」一节里。

这个渠道看不见什么：

  • 登记表当前 0 家公司，所以本渠道现在的实际覆盖面是零。 这不是"这些公司今天没发公告"—— 是一家都还没登记。 登记一家需要人工核对四件事（订阅源地址、robots.txt、transport 实测、核对人与日期）， 代码对未核对的条目一律拒抓（凭印象填的地址返回 404 时， 表现与"这家公司没发公告"完全一样）。
  • 不提供 RSS / Atom 订阅的公司进不了本渠道 —— 这包括多数中国企业的官网， 以及港交所披露易的按公司公告页。而它们恰好是 sec_fts 那条最大盲区所指的同一批公司， 因此本渠道只能部分地补那条盲区，不能补齐。
  • 命中只发生在标题 + 摘要上，不是公告全文。因此本渠道 一行疾病归属都不写（deal_candidate_disease 那张表的 basis 只有 "正文中出现该病名"一个取值）。本渠道进来的候选，疾病归属只能靠人工裁定补。
  • 短语匹配看不见否定：一条写着"本次交易不涉及细胞治疗资产"的公告同样会被判为候选。 这不作为缺陷修 —— 候选一律是"未裁定"，而"未裁定绝不计入交易数"由 deal 表的 CHECK 与页面标签守着。

人工录入　已建成·还没跑过

前两个渠道都覆盖不到、但已由可核验的公开来源报道的交易。 录入表单强制"本信息来自公开来源"勾选，并强制 quote + locator —— 没有这两项的行进不了 deal 表（CHECK 挡着）。

  • 人工录入的覆盖面取决于录入者当天看了什么，因此它永远不能被当成一份清单， 只能当成对前两个渠道的补漏。它没有"跑过一遍"这个概念， 所以本渠道上永远不会出现"今天没有"这种说法。
