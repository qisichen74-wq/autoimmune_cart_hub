召回：为什么是「模态优先全量扫」而不是「按病名检索」

本站不按疾病名去注册库检索，而是先用 query.intr = CAR OR "chimeric antigen receptor" 把干预性研究全量取回 （实测 2905 条），再在本地做疾病分类。

理由是可证明性：按病名检索的漏检必然存在且不可见 —— 实测候选池里有一批试验的 condition 只写「Autoimmune Diseases」这一个笼统标签， 没有任何具体病名可匹配；而走 MeSH 树的 cond="Autoimmune Diseases" 根本不包含克罗恩病与溃疡性结肠炎（它们挂在 Inflammatory Bowel Diseases 下）。 全量扫的代价只有约 2.7 MB，换来的是「没漏」这件事由构造保证，而不是靠病名列全。

候选池里的 2905 条不能叫「2905 项 CAR 试验」

检索式命中的是字面 CAR，其中包含真实噪声： 干预描述里出现 CARS（儿童孤独症评定量表）、E-CAR 量表， 以及字面意义的「汽车」（安全座椅安装、酒驾、机动车事故）。 这些在本地分类时被排除，明细如下 —— 排除必须被看见。

分类：确定性规则，不用模型

condition 字符串到疾病实体的映射全部是可复现规则（token 集合相等 / 连续短语子集 / 单词特异词），规则给不出结论的进人工队列， 裁定结果物化到 config/condition_map.yaml 并留 git diff。 不用大模型分类的原因很直接：分类结果就是「某病有 N 项试验」这个数字， 规则错了可以 diff、可以写测试守住；模型错了只会安静地把 MOGAD 数成 NMOSD， 而且下次跑还可能不一样。

保留意见，按决定执行但不丢信息：同种免疫（GVHD、移植排斥）与 经典自身免疫是不同机制，把它们与 NMOSD、SLE 混成一个计数会得到一个 「自免 CAR 试验数」里含非自身抗原免疫反应的数字。因此每个实体都带类别标签， 默认全部计入（= 使用者的决定），需要分开看时是一句 SQL 而不是一次重跑。

引文回放引擎（src/verify/replay.py）已就位，但抽取管线未上线，所以 deal / evidence_record / ae_record / regulatory_event 四张表都是 0 行。这四张表都带 CHECK(locator_replay_ok = 1)：回放不通过的行根本进不了库，不是入库后标记为待核。因此本站今天不输出任何引文级结论 —— 页面上所有数字都来自注册库结构化字段的确定性分类，不来自对原文的阅读。

因此请不要把本站现有的数字读成「已核对过原文」。它们是注册库结构化字段的确定性分类结果 —— 保证的是「没把 MOGAD 数成 NMOSD」，不是「这个缓解率真的写在那篇文章里」。

机制本身可以现在就核验：python -m src.audit --replay。四张表为空时它报的是「没有检查对象」而不是「通过」—— 空集不等于通过，与导出前那三道闸同一条规矩。

已知盲区（是盲区，不是待办）

  • 干预名与描述都不含 CAR 字样的产品会漏。需要按产品别名定向扫补，尚未做。
  • 字段级变更史在建库之前永久缺失：ClinicalTrials.gov 的历史修订端点返回 403， 替代途径已穷尽。本站的字段级比对只能从 2026-08-22 起累积。
  • 中国 CDE / ChiCTR 尚未接入，NMPA 亦未接入。 候选池里中国申办的试验来自其在 ClinicalTrials.gov 的登记，只登记在国内平台的会漏。
  • 会议摘要（ACR / AAN / ECTRIMS / EBMT）尚未解析。 其中 acrabstracts.org 的 robots.txt 明确 Disallow 了通用抓取代理，须走人工录入。
  • 中文期刊（万方 / 知网 / 维普）没有公开检索接口，且内容许可不允许再分发， 文献层完全看不见它们 —— 而中国研究者的相当一部分自免 CAR-T 报告首发在中文刊上。 这与交易层「非 SEC 申报人看不见」是同一个偏倚方向。
  • 文献层的归属判据在本站不可逐字节回放。 判定由 Europe PMC 服务端做（TITLE_ABS），而本站用 resultType=lite 抓取、 库里没有存摘要正文，所以做不到"在本地重放一次短语匹配"。 因此文献层的归属不进证据表，页面上也不据此给任何疗效结论。

文献层的口径（与试验层完全不同，不可混读）

试验层数的是试验项数，文献层数的是文献篇数， 而后者的判据只是「模态短语与病名短语出现在同一篇文献的标题或摘要里」。 一篇综述的摘要里列举十个适应症，十个病名都会命中 —— 所以「某病 N 篇」不是「某病 N 篇疗效证据」。

  • 预印本与同行评议是两个数，全站不合并。合并成一个「文献 N 篇」 等于把一批未经同行评议的报告算进同一个证据档位。因此文献表里没有合计行。
  • 「某病 0 篇」有四种来源，只有一种能读成"没有"：管线没跑过 / 这个病本轮没有一条查询（分类词表里它只剩被筛掉的裸缩写写法）/ 它的查询有没跑完的 / 全部跑完确实没有。每个疾病档案页上写的是这四种中的哪一种。
  • 检索面被一份短语清单封顶，清单外的写法一篇都不会命中。 已实测的缺口逐条印在文献与预印本页上，带篇数。
  • 纯模态那几条查询在覆盖账里标着"没跑完"，那是主动截断： 本站只要它们的总数当分母，不取那近两万篇文档。它与「这条查询没跑成」分开计数。

不做什么

  • 不处理任何非公开披露信息。交易记录一律要求公开披露渠道， 且「条款未披露」本身作为结论的一部分保留 —— 省掉它会让读者以为条款已知。
  • 不纳入任何受试者层面数据。本站与本机上的受试者数据文件之间不存在代码通路。
  • 不输出投资建议或诊疗建议。涉及具体患者的决策请回到一手资料。
