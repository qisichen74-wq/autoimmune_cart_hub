召回：为什么是「模态优先全量扫」而不是「按病名检索」

本站不按疾病名去注册库检索，而是先用 query.intr = CAR OR "chimeric antigen receptor" 把干预性研究全量取回 （实测 2959 条），再在本地做疾病分类。

理由是可证明性：按病名检索的漏检必然存在且不可见 —— 实测候选池里有一批试验的 condition 只写「Autoimmune Diseases」这一个笼统标签， 没有任何具体病名可匹配；而走 MeSH 树的 cond="Autoimmune Diseases" 根本不包含克罗恩病与溃疡性结肠炎（它们挂在 Inflammatory Bowel Diseases 下）。 全量扫的代价只有约 2.7 MB，换来的是「没漏」这件事由构造保证，而不是靠病名列全。

候选池里的 2959 条不能叫「2959 项 CAR 试验」

检索式命中的是字面 CAR，其中包含真实噪声： 干预描述里出现 CARS（儿童孤独症评定量表）、E-CAR 量表， 以及字面意义的「汽车」（安全座椅安装、酒驾、机动车事故）。 这些在本地分类时被排除，明细如下 —— 排除必须被看见。

分类：确定性规则，不用模型

condition 字符串到疾病实体的映射全部是可复现规则（token 集合相等 / 连续短语子集 / 单词特异词），规则给不出结论的进人工队列， 裁定结果物化到 config/condition_map.yaml 并留 git diff。 不用大模型分类的原因很直接：分类结果就是「某病有 N 项试验」这个数字， 规则错了可以 diff、可以写测试守住；模型错了只会安静地把 MOGAD 数成 NMOSD， 而且下次跑还可能不一样。

疾病名人工队列：待裁定 1 条， 历史已裁定 1149 条。队列的判据是正信号 （字符串带免疫词根但未匹配到任何已登记实体），不是「解释不了的字符串」—— 后者会让队列涨到几百条，等于没有队列。

人工队列是一张共用表，但每一类的判据完全不同，所以数字分开给。 把它们加成一个「待裁定 N 条」，会让读者拿疾病名的判据去解释申办方的候选。 各类当前状况：
· 疑似同一实体的申办方写法：待裁定 29 条，累计 51 条。判据：两条申办方原文共有一个全语料罕见的身份 token；实测真合并命中率约 1/22，故只产候选、绝不自动合并
· 疑似漏检的疾病实体：待裁定 1 条，累计 1150 条。判据：字符串带免疫词根，但未匹配到任何已登记实体 （申办方那一类的判据与清单见申办方页。）

范围口径（使用者 2026-08-22 决定）

  • 移植物抗宿主病、实体器官移植排斥、再生障碍性贫血、过敏（哮喘/鼻炎）、 炎症性肠病伞形标签、化脓性汗腺炎、免疫介导肾病 —— 均计入自免。
  • AL 型淀粉样变 —— 不纳入（浆细胞病，与免疫介导机制不相关）。
  • 移植后淋巴增殖性疾病（PTLD）—— 归入肿瘤参照（移植后淋巴增殖性肿瘤）。
  • 肿瘤专属试验 2296 项入库为参照，只存试验骨架。 留着它们是为了能回答三个问题：同一产品在肿瘤与自免的并行开发路线、 同一靶点在肿瘤的剂量与清淋先例、CRS/ICANS 的安全性先例 （这些数据几乎全在肿瘤试验里，而自免适应症可接受的毒性阈值不同）。

保留意见，按决定执行但不丢信息：同种免疫（GVHD、移植排斥）与 经典自身免疫是不同机制，把它们与 NMOSD、SLE 混成一个计数会得到一个 「自免 CAR 试验数」里含非自身抗原免疫反应的数字。因此每个实体都带类别标签， 默认全部计入（= 使用者的决定），需要分开看时是一句 SQL 而不是一次重跑。

引文回放：数字与原文之间那条可执行的链

未启用 带引文的四张表（交易 / 疗效证据 / 不良事件 / 监管事件）共 0 行。

引文回放引擎（src/verify/replay.py）已就位，但抽取管线未上线，所以 deal / evidence_record / ae_record / regulatory_event 四张表都是 0 行。这四张表都带 CHECK(locator_replay_ok = 1)：回放不通过的行根本进不了库，不是入库后标记为待核。因此本站今天不输出任何引文级结论 —— 页面上所有数字都来自注册库结构化字段的确定性分类，不来自对原文的阅读。

因此请不要把本站现有的数字读成「已核对过原文」。它们是注册库结构化字段的确定性分类结果 —— 保证的是「没把 MOGAD 数成 NMOSD」，不是「这个缓解率真的写在那篇文章里」。

机制本身可以现在就核验：python -m src.audit --replay。四张表为空时它报的是「没有检查对象」而不是「通过」—— 空集不等于通过，与导出前那三道闸同一条规矩。

核验状态：这些结论现在还站得住吗

上面那一段问的是「这句引文出自那个字节吗」，这一段问的是 「支撑这一行的那次抓取还新不新」。两个问题的失效方式正好相反： 引文回放的结论不随时间漂移（raw 被 sha 钉死）， 而核验状态只随时间漂移。所以它们分成两段，各有各的数字。

核验覆盖不到本站自己推导的列：classification、classification_reason、modality_evidence。它们是本站的分类结果，注册库从没说过这句话 —— 而 classification 恰恰是本站最容易出错、最该被质疑的一列。

状态 conflicted 这一层写不出来：含义是「两个独立来源对同一字段给出不同取值」。今天每项试验只有 ctgov 一个来源，交易只有 SEC 一个来源，所以这条路径永远不会写出 conflicted。它是 0 的原因是没有第二个来源可比，不是比过了没有分歧。

覆盖范围：只登记 classification='in_scope' 的试验，加上四张带引文的表。肿瘤参照库的试验不在范围内：它们按设计只存试验骨架、不留快照，登记进来会一律显示成 unverified，而那读起来像「出处断了」，实际是「本站没打算给它留出处」。

已知盲区（是盲区，不是待办）

  • 干预名与描述都不含 CAR 字样的产品会漏。需要按产品别名定向扫补，尚未做。
  • 字段级变更史在建库之前永久缺失：ClinicalTrials.gov 的历史修订端点返回 403， 替代途径已穷尽。本站的字段级比对只能从 2026-08-22 起累积。
  • 中国 CDE / ChiCTR 尚未接入，NMPA 亦未接入。 候选池里中国申办的试验来自其在 ClinicalTrials.gov 的登记，只登记在国内平台的会漏。
  • 会议摘要只解析了 ACR 一个会，AAN / ECTRIMS / EBMT 尚未解析 —— 三个站各自需要一次实测，本站刻意不把 ACR 的解析器套到它们身上。 ACR 这一条只存标题、摘要号、引文与链接，不存摘要正文（版权边界）。
  • 中文期刊（万方 / 知网 / 维普）没有公开检索接口，且内容许可不允许再分发， 文献层完全看不见它们 —— 而中国研究者的相当一部分自免 CAR-T 报告首发在中文刊上。 这与交易层「非 SEC 申报人看不见」是同一个偏倚方向。
  • 文献层的归属判据在本站不可逐字节回放。 判定由 Europe PMC 服务端做（TITLE_ABS），而本站用 resultType=lite 抓取、 库里没有存摘要正文，所以做不到「在本地重放一次短语匹配」。 因此文献层的归属不进证据表，页面上也不据此给任何疗效结论。

文献层的口径（与试验层完全不同，不可混读）

试验层数的是试验项数，文献层数的是文献篇数， 而后者的判据只是「模态短语与病名短语出现在同一篇文献的标题或摘要里」。 一篇综述的摘要里列举十个适应症，十个病名都会命中 —— 所以「某病 N 篇」不是「某病 N 篇疗效证据」。

  • 预印本与同行评议是两个数，全站不合并。合并成一个「文献 N 篇」 等于把一批未经同行评议的报告算进同一个证据档位。因此文献表里没有合计行。
  • 「某病 0 篇」有四种来源，只有一种能读成「没有」：管线没跑过 / 这个病本轮没有一条查询（分类词表里它只剩被筛掉的裸缩写写法）/ 它的查询有没跑完的 / 全部跑完确实没有。每个疾病档案页上写的是这四种中的哪一种。
  • 检索面被一份短语清单封顶，清单外的写法一篇都不会命中。 已实测的缺口逐条印在文献与预印本页上，带篇数。
  • 纯模态那几条查询在覆盖账里标着「没跑完」，那是主动截断： 本站只要它们的总数当分母，不取那近两万篇文档。它与「这条查询没跑成」分开计数。

口径全表（34 条，这一页不折叠）

全站每一个数字旁边都挂着一条口径，形态是一个短标签加一个折叠的长句。 这一页把那些长句全部摊开，一条不折 —— 因为收起的折叠块打印印不出来， 纸面上那些数字旁边只剩短标签。要把某一条口径给别人看，指这里的 #cal- 锚点，而不是让对方自己去某一页展开。

这一节由同一张表生成，不是另抄一遍。两处口径说法不一致比只有一处糟得多： 两处都语法通顺，读者没有办法知道该信哪一处。

不含已停就停着的

这里数的是窗口内状态变成终止类的那些（TERMINATED / SUSPENDED / WITHDRAWN / NO_LONGER_AVAILABLE），判据是本站比对出的那一次状态变化。一项在本站第一次见到它时就已经是终止状态的试验不在这个数里 —— 那是一个状态，不是一件本窗口内发生的事。要看现在有多少项处于终止状态，去全部试验页按状态看。

首次登记日不是发现日

这里数的是窗口内首次登记日落在窗口内的在范围试验。⚠️ 首次登记日是注册库的日期，不是本站发现它的时刻 —— 一项三个月前登记的试验可能是本站上周才召回并归类的，那种情况下它不会出现在这个数里。

数的不是试验数

这里数的是事件条数，不是试验数：一项试验可以同时有多条字段变更（被撤回的那几项同时有状态、停止原因与入组数三条）。而且本站逐日比对的只有那十一个语义字段，刻意不含时间戳与长文本描述 —— 变的若在这些字段之外，它不会出现在这个数里，而会落到「无法定级」那一档。

不与前三格相加

注册库只报告「这条记录被改过」，不报告改了哪个字段；本站比对的只有那十一个语义字段。变的若在那之外（或者只是时间戳），本站就只能说「它变过」。所以这一档没有档位：它的重要性是未知，不是低 —— 给它挂一个最低档等于把「我判不了」说成「我判过、它不重要」。也因此这个数不与前三格相加：它数的不是同一种东西。

唯一可相加的总数

按病计数不可相加：一项 7 个适应症的篮式试验会出现在 7 个疾病档案里，把各病的数字相加会得到一个没有意义的总数。这一个数是例外 —— 它按去重后的试验条数计，也是全站唯一可以当作总量引用的那个。

只存骨架·不计入自免

肿瘤试验入库只是为了当参照：只存试验骨架，没有干预名、没有快照、不做疾病分类。所以它既回答不了「同一个 CAR 在肿瘤走到哪一步」，也不许与自免那一侧的试验数相加。

判为不在范围

检索命中、但本地分类判定它既不是自免/神经免疫、也不作肿瘤参照的那些。判错的方向是把在范围的判出去 —— 所以这个数越大越该抽查，它不是一个业绩指标。

0 命中也是一个实体

分母是本站登记的全部疾病实体，分子是今天在注册库里查到过至少一项试验的。两者之差不是「待办」：那些实体本站查过，结果确实是 0，而 0 是观测结果。

连接数 > 试验数

一项篮式试验同时招多个适应症，于是它在每个相关疾病下各留一条连接。所以连接数比试验数大，而这也正是按病计数不可相加的成因：把各病的试验数加起来，等于把同一项篮式试验数了好几遍。

三处盲区·未覆盖

范围止于公开可核验的登记与披露。已知在盲区内的三类：中国 CDE/ChiCTR 的登记（注册库不同，本站今天不读）；干预名与描述里都不出现 CAR 字样的产品（检索端就漏掉了，本地分类补不回来）；未公开披露的交易条款（只处理公开披露的内容，未披露的一律不猜）。

未启用 ≠ 今天没有

每条流各自标状态，三种「空」在本站长得不一样：「未启用」是本站还没开始采集；「累积中」是在采但还不完整，那个数只是下限；「已启用·该区间 0 条」是采集正常而区间内确实没有记录 —— 只有这一种是观测结果。本站不把任何一种渲染成空白：空白会被读成「这个领域最近没动静」。

同公司 ≠ 同产品

两边都出现只说明这家公司在自免与肿瘤同时在做，不说明那是同一个产品的两条路线。按产品答本站今天答不了：肿瘤参照只存试验骨架，库里没有它们的干预名。

经验厚 ≠ 可外推

肿瘤侧规模之所以值得看，是因为清淋强度、CRS/ICANS 的处理经验与剂量先例几乎都积累在肿瘤试验里。但自免适应症可接受的毒性阈值与肿瘤不同 —— 肿瘤经验厚不等于能直接外推到自免，这一条与本站抓到多少数据无关，是口径问题。

排版 ≠ 数据时刻

导出可以在没有任何新数据的日子里重跑，那时排版时刻会变而数据时刻不会。做判断一律看「试验数据截至」那一个时刻，不要看排版时刻。

专病 · 不含篮式

「专病」= 该试验登记的适应症就是本病。篮式试验不算进这个数 —— 把一项 7 个适应症的篮式试验算成本病的专病试验，虚增的正是最受关注的那个数字。

样本量分摊 · 不属本病

篮式试验同时招多个适应症：样本量在各适应症之间分摊，而且多数不预设按适应症的分层分析。所以这些数字属于那些篮子，不属于本病 —— 它们与专病试验的可解读性不同。

关系未定 · 还没裁

这些试验的 condition 命中了本病，但连接角色还没有被裁定成专病或篮式。它既不该被当成专病数的一部分，也不该被当成篮式 —— 它是一批待裁定的连接。

按病计数不可相加

本页的合计按去重后的试验条数计，只在本页内成立。它不可与其他疾病页的数字相加：一项篮式试验会同时出现在多个疾病档案里，相加等于把同一项试验数了好几遍。

上卷去重 · 不可相加

「含子实体上卷」是把子实体页的试验并进来、再去重之后的条数。所以父实体与子实体那两个数不可相加：同时登记了两者的试验只算一次。

别名不完整 · 不收亚型名

别名与缩写是人工逐条维护的，而且刻意不收亚型名 —— GPA、皮肌炎、冷抗体型 AIHA 都不作为别名列出，因为亚型是不同的实体。所以 Ctrl+F 找不到某个写法，只说明这份表里没写，不说明本站没有这个病。

原文逐字 · 判错请报

每一行都给出注册库里的 condition 原文和命中它的那条规则，是为了让你自己判断这些试验算不算本病，而不必信任分类层。任一条判错请写进 config/condition_map.yaml。

两栏之间没有合计

专病与篮式两栏之间不给合计，也不给任何一个把两边加起来的数字。这不是版面偏好：把两栏相加的那个式子里，等号左边两项的单位不同 —— 一边是「适应症就是这个病的试验」，另一边是「含这个病的篮子」，而篮子的样本量在各适应症之间分摊。

伞形 · 未指名本病

那些试验只登记了「自身免疫病」这类笼统适应症，没有指名具体实体 —— 所以它们既没被算进本页的任何一个数字，也不能被断定与本病无关。

清单外的写法不命中

本病的检索只用这里列出的那几条短语，清单外的写法一篇都不会命中。所以本病的文献篇数是由这几条短语决定的一个下界，不是全世界的文献量。

各类别均计入自免

类别标签只是标签，不是范围划分：下列全部类别（含同种免疫、过敏、自身炎症）均计入本站的「自免」口径。按使用者 2026-08-22 的决定保留类别，是为了需要分开看时不必重跑 —— 例如「不含移植相关的自免试验数」是一句 SQL。AL 型淀粉样变按同一决定不纳入（克隆性浆细胞病，非免疫介导）；移植后淋巴增殖性疾病（PTLD）归入肿瘤参照。

有命中含篮式

「有命中」= 该实体在至少一项在范围试验里被登记为适应症，而且含篮式 —— 一项 7 个适应症的篮式试验会让 7 个实体同时算「有命中」。所以这个数回答的不是「有多少个病被专门研究过」，那个问题要看各卡片的「专病」那一格。

观测结果 · 不是缺失

这些实体本站逐个查过，结果是 0 项。0 不等于「还没查」，也不等于「本站没有这个病」—— 各自的页面都在，并且各自说明这个 0 的外推边界。

单位是文档 · 不是交易

这个数数的是候选文档份数：一份申报可能提到多笔交易，一笔交易也可能被多份申报各提一次。所以它既不是交易数，也不是「有多少家公司在做交易」——它唯一能回答的问题是「有多少份文档进了待读队列」。

读过原文才落一行

只有已经有人读过原文、并且原文引用能逐字节回放的交易才进这个数（回放不通过的行插不进库，有 CHECK 挡着）。所以它是一个下界，而且它不随候选池一起长 —— 候选池涨一千份，这个数照旧不动。

还没查 ≠ 查过没有

「从未做过归属」是这份文档还没有被查过病名；「查过、一个已登记病名都没出现」是查过、结果确实是没有。两个数在页面上长得一样、含义相反，所以本站既不把它们相加，也不合并成一个「无归属 N 份」。

渠道数 ≠ 覆盖面

这个数数的是本站声明过的渠道条数。声明过不等于有数据 —— 里面既有正在跑的，也有机制建成、但还没有任何抓取对象的，还有一次都没跑过、甚至还没建成的。哪一条是哪一种，只看每条渠道标题旁边那个状态标签：本站不把「渠道已声明」渲染成「这个渠道有数据」。

不是分母 · 是本站查到的那一块

这个数是本站库内的文献条数，而「整个 CAR 文献有多大」是另一个数（在下面「分母」那一节里，量级大得多）。拿这个数当分母算出来的任何比例都是错的 —— 它衡量的是本站那几条短语捞到了多少，不是这个领域有多少。

缺席的渠道不产生 0

这一格与旁边那个「声明的渠道」之差，就是本站现在看不见的那几条渠道。它们不产生 0，也不产生任何一行 —— 缺席的方式是「不出现」，读者在清单里不会撞上任何提示。所以这两个数必须并排印。

衡量的是清单窄 · 不是文献少

伞形宽网捞到、而本站病名清单认领不了的篇数。它会随病名清单变长而变小 —— 也就是说这个数描述的是本站清单有多窄，不是这些文献本身有什么问题。所以它不该被读成「这些文献与自免无关」。

报一条错分类

每个疾病档案的试验表里，每一行都印着注册库的 condition 原文 和命中它的那条规则。判错了请把那条 condition 原文写进 config/condition_map.yaml，连同它该归到哪个实体 ——或者「不属于任何已登记实体」，那也是一条裁定。

为什么是这个文件而不是改规则：规则给不出结论的字符串本来就走人工裁定， 而这个文件就是那份裁定的落处，一次改判等于一行文本差异，看得见是谁把哪个字符串判到了哪里。 直接去改规则会顺带动到别的字符串，而那些字符串的判定没有人复核过 —— 表现是「修好一条、静默改动几十条」。

已声明、还没建成（是空表，不是「查过为 0」）

下面这些层库里已经有表、一行数据都没有。 它们与「查过、结果确实是 0」必须分开说，因为两者在页面上长得一模一样： 一个空表渲染出来就是一个 0。这里列的是会在页面上露出一个 0 的那几层， 不是库里全部空表的清单。

  • 已裁定的交易（deal）—— 发现层每晚在跑、候选池在涨， 裁定层还没有人读过原文。交易情报页上那个 0 是这个意思， 不是「本领域最近没有交易」。 公司新闻稿那条渠道的登记表还是空的，先登哪几家可以按本站试验数排出来： python -m src.pipeline.company_pr --worklist。
  • 疗效与安全性数据（cohort / cohort_observation / endpoint / ae_record）—— 本站今天不存任何队列级结果、 终点数值或不良事件记录。这就是全站一处疗效结论也不给的原因， 而不是因为口径谨慎。
  • 产品与产品别名（product / product_alias）—— 所以「同一家公司」问不到「同一个产品」， 申办方页那条口径是这件事的后果，不是一句免责声明。
  • 已核验的阴性结论（verified_negative）—— 「查过、确实没有」今天只在各疾病页上按病陈述，还没有单独物化成可回放的记录。 也就是说那些 0 的可核验性弱于那些非 0 的数。
  • 监管事件（regulatory_event）、叙述性记录（narrative）、 证据记录（evidence_record）—— 表已建，一行都没有。

运行内务（这一节不改变上面任何一个数字的读法）

这一节是从首页横幅搬过来的。它回答的是「今晚采集稳不稳」， 不回答「这个数字该怎么读」—— 后者一律留在数字旁边，一句也没有搬走。 ⚠️ 数据一旦过期，下面这几个数会同时回到首页横幅上： 要判断「为什么它停在那个时刻」时，线索必须在眼前，不能在另一页。

最近一次刷新过试验数据的成功运行：第 205 次 · 作业 weekly · 候选 2959 → 纳入 343。累计刷新过试验数据的成功运行 39 次，过期阈值 192 小时。

另有 11 次运行永久停在 status=running， 未计入任何一侧。它们既没收尾也没标失败（进程被杀、机器休眠都会这样）， 所以本站不能把它们算成成功，也不能算成失败 —— 只能单独报数。

另有 92 次成功运行只涉及其他数据层（交易发现）， 它们不刷新试验数据，因此不计入「试验数据截至」那个时刻。 交易层自己的覆盖账见交易情报。

上次试验数据刷新之后，另有 0 次 只涉及其他数据层的运行失败 —— 不影响试验数字， 但交易板块的覆盖面可能因此不完整。

定时任务用的是 /IT（交互式）： 机器在计划时间休眠或关机时，任务静默不运行，既不失败也不留记录。 所以「上次成功」与「今天」之间出现空档时，第一个该排除的原因是机器没开机， 而不是采集失败 —— 这两者在库里长得不一样（后者会进上面那个失败计数）。

页面上那些「可以自己数一遍」的数

本站有几处刻意把同一个量的两个来源并排印出来，让读者不必相信、 可以自己核对。这一节集中说明它们；各页上只留那句主张本身，不重复解释。

  • 全部试验页的行数：那一页印着「全部 N 项 · 已全部列出，无截断、无分页」， 并在旁边给出「行数 N ＝ 在范围总数 N」。两个数来自两条不同的查询 （一条取全部在范围试验、一条按分类档位计数）。它们相等是这一页的全部价值 —— 不相等时那条横幅会换成红色的缺陷横幅，而不是照样印「已全部列出」。 那是刻意的：两数不等只可能是取数口径漂开了，而那是个必须被看见的缺陷。
  • 候选池的分解式：首页印着「候选池 ＝ 自免 ＋ 肿瘤参照 ＋ 判为不在范围 ＋ 未分类」。 各项相加必须等于总数；这是本站唯一一处鼓励读者做加法的地方。
  • 疾病页的两栏分布：专病与篮式永不相加 —— 篮式试验的样本量在各适应症之间 分摊，把两栏加起来会得到一个没有意义的数。所以那两栏连列都不共享。
  • 筛选条的分母：筛选时印「显示 m / 共 n 项」，其中 n 由服务端渲染、 JS 只读不算。各档计数之和必须等于分母，否则导出直接失败 —— 不穷尽的轴会把一部分条目筛成「既不在任何一档里、也没人发现它被筛掉了」。 ⚠️ 靶点那一轴是例外：它是多值的（一项双靶试验同时落两档）， 所以各档可相加大于总数，而那一行上印着这句限定。

本站有一段 JavaScript，它只做三件事

本站现在带一段 assets/site.js。在那之前全站零 JS， 而那条决定是刻意的 —— 这一节说明它现在做什么、以及关掉它会怎样。

  • 表头排序（只在「全部试验」那一页）。准入条件由代码把关： 一张表的行数必须等于它声明的总数。本站有十几处「共 N 项，上表只列最近 N 条」， 给那样一张表加排序等于排出一个假的 Top-N —— 读者按某一列排出来的「最前几项」 只是已列出那几行里的最前几项，而页面不会说这件事。
  • 筛选（「全部试验」与「注册试验动态」两页）。分母由服务端渲染， JS 只读不算；各档计数之和必须等于分母，否则导出直接失败。 筛选会隐藏不匹配的条目，而浏览器自带的 Ctrl+F 找不到被隐藏的内容 —— 这句话常驻印在筛选条上，不是藏在这一页里。
  • 本页检索。它不是全站搜索，只在当前页已列出的条目的文字里找。 刻意如此：一个静默返回 0 结果的全站搜索框会制造本站第四种无法区分的空 （没查过 / 查过是 0 / 没建成 / 搜不到），而本页检索的 0 结果能说清 「这一页索引了什么、没索引什么」。

关掉 JavaScript 之后：没有任何控件、所有条目完整可见、 行序与页面上印着的那句行序声明一致。也就是说退化态就是完整态 —— 页面上每一句话在没有 JS 的情况下仍然是真的。本站刻意不做 loading / spinner /「暂无数据」这类中间态：那些东西在 JS 失效时会让页面 主动断言一个零，而那是本站最不能犯的错。

「IIT」怎么判的，以及为什么仍然答不了「有没有 IND」

本站把一项试验分成三类 —— IIT（研究者发起研究）、企业申办、 政府/公立机构发起。判据只有一条：牵头申办方的机构性质， 而那是注册库自己给的字段（LeadSponsorClass），本站照抄、不另做判断。

  • IIT ← 注册库把牵头申办方标成学术机构（医院、大学或个人研究者）。 实测这一档里排在前面的是浙江大学、同济医学院协和医院、浙大儿院、 中国医学科学院血液病医院、同济医院、陆道培医院 —— 都是 IIT 申办方。
  • 企业申办 ← 标成企业。实测前几名是诺华、重庆精准、南京北恒、 Cabaletta、Kyverna、驯鹿/合源一类。
  • 政府/公立机构发起 ← 标成政府机构。

为什么这个标签比「期别」有用。 343 项在范围试验里有 230 项落在 I 期家族，III 期只有 6 项 —— 也就是说「期别」这一列几乎不携带信息。 而研究类型与期别交叉之后才看得见形状： 企业申办的试验里有 37% 进到 II 期及以上，IIT 是 15%。 光看期别看不见这个差别。下面这张表是完整的交叉口径：

三条必须跟着这个标签走的限制。

  • 注册库把医院、大学与个人研究者都归进同一档，本站分不出三者。 对「是不是 IIT」这个判定来说这不是问题（三者都是 IIT 申办方）， 但这一列答不了「是医院牵头还是某位研究者牵头」。
  • 「政府/公立机构发起」那一档共 4 项，里面混着一家省级医院。 按「申办方是医院就算 IIT」的判据它们也是 IIT，但注册库把它们标成了政府机构 —— 本站照抄注册库、不替它改判，所以那 3 项留在政府那一档。 要按「医院牵头」口径看，得把这两档一起看。
  • 申办方性质是提交者自己填的。一项实际由企业推动、而以医院名义登记的试验， 在这一列里会显示成 IIT。本站没有办法发现这种情况。

「有没有 IND」仍然答不了，而且这不是还没做。 IIT 与 IND 是两个轴：一位主要研究者可以自己持有 IND（IIT + 有 IND）； 一家企业在本国开展的试验可能根本没有美国 IND（企业申办 + 无 IND）。 而本站没有任何责任方（responsible party）、监管归属、是否受 FDA 监管、 是否持有 IND 的字段 —— 连保存下来的注册库原始快照里都没有， 所以连回溯都做不到，要取这些信息必须改召回层。 国内语境里的「IIT 对注册临床」还关系到药监申报，而那在 ClinicalTrials.gov 上完全看不见。

所以：这一列能回答「谁发起的」，不能回答「走的哪条监管路径」。

不做什么

  • 不处理任何非公开披露信息。交易记录一律要求公开披露渠道， 且「条款未披露」本身作为结论的一部分保留 —— 省掉它会让读者以为条款已知。
